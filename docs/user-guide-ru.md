## Начало работы

### Требования

- Docker и Docker Compose (рекомендуется), или Go 1.22+ / Node.js 18+ / PostgreSQL 18+

### Установка (Docker)

```bash
git clone https://github.com/AlexsandrKotov/pepa.git
cd pepa
make docker-up
```

Откройте портал по адресу **http://localhost:3000**

### Локальная разработка

```bash
# Запуск инфраструктуры
docker compose -f deployments/compose/docker-compose.yml up -d postgres redis minio minio-init

# Сборка и запуск API
make build && make run-dev

# Запуск воркера (отдельный терминал)
make run-worker

# Запуск фронтенда (отдельный терминал)
cd frontend && npm install && npm run dev
```

### Архитектура

```
┌─────────────┐     ┌──────────────┐     ┌──────────────┐
│   Фронтенд   │────▶│  API Сервер  │────▶│  PostgreSQL  │
│  (Next.js)   │     │   (Gin/Go)   │     │  + PGvector  │
│  Порт 3000   │     │  Порт 8080   │     │  Порт 5432   │
└─────────────┘     └──────┬───────┘     └──────────────┘
                           │
              ┌────────────┼────────────┐
              │            │            │
        ┌─────▼─────┐ ┌─────▼─────┐ ┌──▼──────────┐
        │   Redis    │ │   MinIO   │ │  Trivy DB   │
        │ (Очередь)  │ │ (S3/Арт.) │ │ (Скан. уязв.)│
        └───────────┘ └───────────┘ └─────────────┘
```

API сервер также управляет базами данных Trivy — автоматически загружает и обновляет их при установке плагина Trivy. Подробнее см. [Сканирование безопасности](#сканирование-безопасности).

## Авторизация и администрирование

### Учётная запись администратора по умолчанию

|------|----------|

1. Откройте **http://localhost:3000/login**

| Роль | Доступ |
|------|--------|

- Связи с другими сервисами (граф)
- История развёртываний
- Результаты проверок здоровья
- Оценка по оценочной карте

### Создание сервиса

1. Нажмите **Развернуть** или **Сервисы → Развернуть сервис**
2. Выберите шаблон:
   - **Node.js API** — Express, 200m CPU, 256Mi RAM
   - **Go API** — Gin, 100m CPU, 128Mi RAM
   - **Python API** — FastAPI, 200m CPU, 256Mi RAM
   - **Static Site** — HTML, 50m CPU, 64Mi RAM
   - **Helm Import** — Импорт существующего Helm чарта
3. Заполните имя сервиса, команду и конфигурацию
4. Нажмите **Развернуть**

## GitOps рабочие процессы

### Обзор GitOps

PEPA использует принципы GitOps для развёртываний:

```
  Git Репозиторий (Единый источник истины)
       │
       ▼
  FluxCD Агент (следит за изменениями)
       │
       ▼
  Кластер Kubernetes (применяет желаемое состояние)
       │
       ▼
  Проверка (health checks + откат)
```

### Обнаружение дрейфа

Перейдите в **GitOps → Обнаружение дрейфа** для:
- Просмотра различий между состоянием в Git и реальным состоянием кластера
- Выявления ручных изменений, обошедших GitOps
- Запуска синхронизации для восстановления желаемого состояния

### Настройка репозитория

1. Перейдите в **GitOps** и выберите репозиторий
2. Настройте ветку и путь для мониторинга
3. Установите интервал синхронизации и параметры авто-исправления
4. PEPA проверит конфигурацию и начнёт наблюдение

## RBAC — Роли и права доступа

## Сканирование безопасности

PEPA включает встроенное сканирование уязвимостей на базе [Trivy](https://aquasecurity.github.io/trivy/). Сканируйте контейнеры, файловые системы, git-репозитории и IaC-конфигурации на наличие CVE и ошибок конфигурации.

### Автоматическое управление базами данных

При установке плагина Trivy через Маркетплейс, API сервер **автоматически загружает** базы данных уязвимостей (`trivy-db` и `trivy-java-db`) и обновляет их в фоне. Отдельный контейнер или ручная настройка не требуются.

- **Автозагрузка**: БД загружаются сразу при установке плагина
- **Автообновление**: БД обновляются каждые 6 часов (настраивается)
- **Фоллбэк**: Если основной реестр недоступен, автоматически используется GHCR
- **Пользовательские реестры**: Смена источника БД в runtime через API

### Установка плагина Trivy

1. Перейдите в **Маркетплейс** → найдите **Trivy Security Scanner**
2. Нажмите **Установить** — базы данных загружаются автоматически
3. Плагин готов к использованию

Через API:
```bash
curl -X POST http://localhost:8088/api/v1/marketplace/trivy/install \
  -H "Authorization: Bearer $TOKEN"
```

### Проверка статуса баз данных

```bash
curl -H "Authorization: Bearer $TOKEN" \
  http://localhost:8088/api/v1/security/db-status
```

Ответ:
```json
{
  "trivy_db": { "available": true, "updated_at": "...", "size_bytes": 1073741824 },
  "java_db": { "available": true, "updated_at": "...", "size_bytes": 536870912 },
  "trivy_version": "Version: 0.74.0"
}
```

### Запуск сканирования

#### Через веб-интерфейс
1. Перейдите в **Безопасность** → **Цели сканирования**
2. Нажмите **Добавить цель**
3. Выберите тип сканера: **Trivy**
4. Настройте цель (имя образа, URL репозитория или путь)
5. Нажмите **Сканировать**

#### Через API
```bash
curl -X POST http://localhost:8088/api/v1/security/targets \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "target_ref": "nginx:latest",
    "scanner_type": "trivy",
    "scan_config": {
      "scan_type": "image",
      "severity": "HIGH,CRITICAL"
    }
  }'
```

### Типы сканирования

| Тип | Описание | Пример цели |
|------|-------------|----------------|
| `image` | Сканирование уязвимостей контейнера | `nginx:latest` |
| `fs` | Сканирование файловой системы | `/app` |
| `repo` | Сканирование git-репозитория | `https://github.com/org/repo` |
| `config` | Сканирование IaC (Terraform, K8s, Dockerfile) | `/terraform` |

### Пользовательский реестр БД

Для использования приватного или пользовательского зеркала БД:

```bash

curl -X PUT http://localhost:8088/api/v1/security/db-repository \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"db_repository": "ghcr.io/aquasecurity/trivy-db"}'

# Или установить плагин с пользовательским реестром

  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \

```

### Ручная загрузка БД

```bash
curl -X POST http://localhost:8088/api/v1/security/db-download \
  -H "Authorization: Bearer $TOKEN"
```

### VEX-документы (фильтрация ложных срабатываний)

VEX-документы (Vulnerability Exploitability eXchange) позволяют фильтровать ложные срабатывания:

1. Разместите VEX-файлы (формат OpenVEX или CycloneDX) в `deployments/compose/trivy-vex/`
2. Укажите их в конфигурации сканирования:
```json
{
  "target_ref": "my-app:latest",
  "scanner_type": "trivy",
  "scan_config": {
    "vex": "/etc/trivy/vex/my-app-vex.json"
  }
}
```

## Устранение неполадок

### Частые проблемы

#### 1. Не удаётся подключиться к кластеру Kubernetes

**Симптомы:** Кластер показывает статус "Отключён"

**Решения:**
- Проверьте валидность kubeconfig: `kubectl --kubeconfig=<file> get nodes`
- Проверьте сетевую связность с API сервером кластера
- Убедитесь, что kubeconfig имеет достаточные RBAC права
- Перезагрузите kubeconfig если срок действия истёк

#### 2. Фронтенд показывает пустую страницу

**Симптомы:** Белый экран, ошибки в консоли

**Решения:**
- Очистите кэш и cookies браузера
- Проверьте, что API сервер запущен: `curl http://localhost:8080/healthz`
- Проверьте переменную `NEXT_PUBLIC_API_URL`
- Проверьте консоль браузера на ошибки CORS — обновите `CORS_ORIGINS` в конфигурации

#### 3. Пайплайн падает на шаге "deploy"

**Симптомы:** Пайплайн показывает красный на шаге deploy

**Решения:**
- Проверьте связность кластера в **Подключения**
- Убедитесь, что целевой namespace существует в кластере
- Проверьте, что FluxCD установлен и запущен в кластере
- Проверьте логи пайплайна на конкретные ошибки Kubernetes

#### 4. AI Ассистент возвращает ошибки

**Симптомы:** AI чат показывает "Не удалось получить ответ"

**Решения:**
- Проверьте, что API ключ AI провайдера настроен в **Настройки → AI**
- Проверьте сетевую связность с endpoint AI провайдера
- Убедитесь, что у аккаунта AI провайдера достаточно кредитов/квоты

#### 5. Ошибка подключения к базе данных

**Симптомы:** API возвращает ошибки 500, логи показывают "connection refused"

**Решения:**
- Проверьте, что PostgreSQL запущен: `docker compose ps`
- Проверьте переменные `POSTGRES_HOST`, `POSTGRES_PORT`, `POSTGRES_PASSWORD`
- Убедитесь, что база данных существует: `psql -h localhost -U pepa -l`
- Запустите миграции: `psql -h localhost -U pepa -d pepa -f migrations/001_initial_schema.sql`

#### 6. Плагин не загружается

**Симптомы:** Плагин показывает статус "Ошибка"

**Решения:**
- Проверьте, что бинарный файл плагина существует в директории `plugins/`
- Убедитесь, что плагин скомпилирован для правильной архитектуры
- Проверьте логи API сервера на ошибки загрузки плагина
- Переустановите плагин из Маркетплейса

#### 7. Обнаружен дрейф GitOps

**Симптомы:** Обнаружение дрейфа показывает различия

**Решения:**
- Просмотрите детали дрейфа для понимания что изменилось
- Если изменение было намеренным, обновите репозиторий Git для соответствия
- Если изменение было случайным, запустите синхронизацию со страницы GitOps
- Рассмотрите включение авто-исправления для автоматической синхронизации дрейфа

#### 8. БД Trivy показывает «Недоступно»

**Симптомы:** На странице безопасности показано «Недоступно» для Vulnerability DB

**Решения:**
- Убедитесь, что плагин Trivy установлен через Маркетплейс
- Запустите ручную загрузку БД:
  ```bash
  curl -X POST http://localhost:8088/api/v1/security/db-download \
    -H "Authorization: Bearer $TOKEN"
  ```
- Проверьте логи API сервера: `docker logs pepa-api | grep trivy`
- Проверьте сетевую связность с реестром БД
- Попробуйте другой реестр:
  ```bash
  curl -X PUT http://localhost:8088/api/v1/security/db-repository \
    -H "Authorization: Bearer $TOKEN" \
    -d '{"db_repository": "ghcr.io/aquasecurity/trivy-db"}'
  ```

## Часто задаваемые вопросы

### Как сбросить пароль администратора?

Используйте CLI:
```bash
./bin/pepa user reset-password --email admin@pepa.dev --password newpassword
```

Или через API:
```bash
curl -X PUT http://localhost:8080/api/v1/users/<id>/password \
  -H "Content-Type: application/json" \
  -d '{"password": "newpassword"}'
```

### Как добавить новое окружение?

Перейдите в **Настройки → Окружения → Создать окружение**. Укажите имя, переменные и ограничения.

### Можно ли импортировать существующие Helm чарты?

Да. Используйте шаблон **Helm Import** при создании сервиса, или добавьте Helm репозиторий в **Helm Репозитории**.

### Как включить продакшен режим?

Установите переменные окружения:
```bash
SERVER_ENV=production
DEV_MODE=false
JWT_SECRET=your-secret-key
```

### Как сделать резервную копию базы данных?

```bash
docker compose exec postgres pg_dump -U pepa pepa > backup_$(date +%Y%m%d).sql
```

### Как масштабировать API сервер?

API сервер не имеет состояния. Запустите несколько экземпляров за балансировщиком нагрузки:
```bash
docker compose -f docker-compose.prod.yml up --scale api=3 -d
```

### Как запустить сканирование уязвимостей?

Установите плагин Trivy через Маркетплейс — базы данных загрузятся автоматически. Далее:
1. Перейдите в **Безопасность → Цели сканирования → Добавить цель**
2. Выберите тип сканера: **Trivy**
3. Введите цель (имя образа, URL репозитория или путь)
4. Нажмите **Сканировать**

Или через API:
```bash
curl -X POST http://localhost:8088/api/v1/security/targets \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"target_ref": "nginx:latest", "scanner_type": "trivy"}'
```

### Как изменить источник БД Trivy?

Используйте пользовательское или приватное зеркало БД:
```bash
curl -X PUT http://localhost:8088/api/v1/security/db-repository \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"db_repository": "ghcr.io/aquasecurity/trivy-db"}'
```

### Как проверить статус баз данных Trivy?

```bash
curl -H "Authorization: Bearer $TOKEN" \
  http://localhost:8088/api/v1/security/db-status
```

Если БД показывает «Недоступно», запустите ручную загрузку:
```bash
curl -X POST http://localhost:8088/api/v1/security/db-download \
  -H "Authorization: Bearer $TOKEN"
```
